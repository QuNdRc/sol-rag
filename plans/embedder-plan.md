# План: свой классический эмбеддер на C++ (BoW → TF-IDF → опция LSA)

> Референс «как не изобретать велосипед заново». Цель — написать руками
> свой эмбеддер, который превращает текст в float-вектор и стыкуется
> с `VectorStorage` из проекта Sparse-RAG. Никаких внешних библиотек.

## Место в системе

```
текст --(токенизатор)--> токены --(словарь)--> id --(tf*idf)--> веса --(L2-норм)--> VectorStorage
```

- Интерфейс: `std::vector<float> embed(std::string_view text)`.
- Реализация: `TfIdfEmbedder` (классический), позже `LlamaCppEmbedder` (тот же интерфейс).
- **Важно про размерность:** у классического эмбеддера `dim = размер словаря` (сотни/тысячи).
  `VectorStorage::dim` — просто константа, ставь её равной размеру словаря. Математика та же.
- `VectorStorage::add_vector()` сам нормирует на входе (L2), поэтому эмбеддер отдаёт
  сырые веса `tf*idf` — единичную длину сделает хранилище.

## Структура файлов в новом решении

```
embedder/
  embedder.h          — интерфейс Embedder + TfIdfEmbedder
  embedder.cpp
  tokenizer.h/.cpp    — текст -> токены
  vocabulary.h/.cpp   — токен -> id (frozen после fit)
  tfidf.cpp           — расчёт idf, векторизация, нормализация
  lsa.h/.cpp          — ОПЦИЯ: SVD снижение размерности
  persistence.h/.cpp  — дамп/загрузка словаря + idf + индекса
```

На первый проход достаточно `embedder.h/cpp + tokenizer + vocabulary + tfidf`.
`lsa` и `persistence` — отдельные ступени, не блокирующие первые шаги.

## 1. Токенизатор (в первую очередь)

Задача: `std::string` -> `std::vector<std::string>`.

Правила (по нарастающей, добавляй по одному):
1. lowercase (русские буквы + латиница);
2. заменить `ё` на `е` (много коротких текстов хранят «е»);
3. разбить по `isalpha` / по пробелам, убрать пунктуацию и управляющие;
4. отбросить токены короче 2 символов (шум);
5. ОПЦИЯ: примитивный стемминг — «срезать хвост» (суффиксы) с копилкой
   пар слово->основа. Не увлекаться: для СНиПов терминология стабильна, стемминг даёт мало.

На этом этапе вообще не нужен словарь — только функция `split`.

## 2. Словарь (Vocabulary)

Задача: токен -> стабильный `size_t id`, и наоборот.

- Хранение: `std::unordered_map<std::string, size_t> token_to_id`;
  `std::vector<std::string> id_to_token` (для дампа и дебага).
- `id` присваивай по порядку ПЕРВОГО появления в корпусе — векторы станут
  предсказуемыми и воспроизводимыми.
- После фита словарь **замораживается**: на фазе запроса НЕ аккуратно добавлять
  новые токены, иначе размерность поплывёт (см. OOV ниже).

## 3. BoW-вектор (первый «запуск», чтобы почувствовать)

- Размерность `V = token_to_id.size()`.
- Для чанка: счётчик токенов -> плотный `std::vector<float>` длины `V`
  (или спарс-карта на время построения, конвертируешь в плотный в конце).
- Прогнать на СНиП-чанках: топ-1 по запросу должен быть логичным (общие термины => выше косинус).
- Это и есть «игрушечная семантика»: совпали слова — значит близко.

## 4. TF-IDF (главный шаг, он же уровень «смысла дальше совпадения слов»)

Формулы (вариант со сглаживанием, не натыкаешься на деление на 0):

```
tf(t, doc)   = count(t, doc)                        // частота токена в чанке
df(t)        = число чанков, где встречается t
idf(t)       = ln( (1 + D) / (1 + df(t)) ) + 1      // D = число чанков в корпусе
weight(t, doc) = tf(t, doc) * idf(t)
```

- `idf` считается ОДИН раз после фита по всему корпусу (проход по чанкам).
- IDF делает редкие (и потому важные, терминологичные) слова «тяжелее» общих («и», «что»).
- Сравни топы BoW vs TF-IDF: у TF-IDF редкий термин из запроса должен поднимать нужный чанк выше.

## 5. Нормализация

- Вектор `embed()` должен иметь единичную L2-норму, ЕСЛИ ты вызываешь dot напрямую
  (вне `VectorStorage`). Сам `VectorStorage::add_vector` нормирует — дублировать можно
  необязательно, но для самопроверок удобно.
- Если пишешь тест без хранилища — нормируй в эмбеддере сам.

## 6. ОПЦИЯ: LSA/SVD (снижение размерности, «ловля синонимики»)

- Цель: V (тысячи) -> k (например, 100–300) координат.
- Строим матрицу чанк-термин, делаем SVD (односторонняя итерация / Якоби руками),
  оставляем k сингулярных векторов, проектруем.
- Это ловит скрытые корреляции: «кухонное помещение» начнёт ближе к «кухня».
- Уровень Б: не блокирует; это отдельная ступень, когда BoW/TF-IDF уже ощущается.
- Не превращай SVD в главную цель — изучи после того, как ясно почувствуешь TF-IDF.

## 7. OOV и «заморозка» словаря (важная ловушка)

- Токены, которых нет в словаре (Out-Of-Vocabulary), на фазе запроса **пропускай** (вес 0)
  или хэшируй в бакет фиксированной размерности (feature hashing). Не добавляй в словарь!
- Словарь frozen -> размерность стабильна -> вектор запроса той же длины, что и векторы чанков.
- Если так не сделать: `embed(query)` выдаст вектор другой длины и косинус станет бессмыслицей.

## 8. Интеграция с VectorStorage (интерфейс)

```cpp
struct Embedder
{
    virtual ~Embedder() = default;
    virtual std::vector<float> embed(std::string_view text) const = 0;
};
```

Ингестия:
```
для каждого чанка:  emb = embedder.embed(chunk_text)
                    storage.dim = vocab_size()   // один раз
                    storage.add_vector(emb.data(), emb.size(), chunk_text)
```

Запрос:
```
q = embedder.embed(question)     // той же размерности
top = storage.search_top_k(q.data(), k)
```

## 9. Персистентность (ОПЦИЯ, для скорости старта)

- Дамп: `token_to_id` + `idf` + уже эмбедженные чанки (`all_dimensions` + `raw_texts`).
- Простой бинарный формат: пиши длину, потом массив байт/флоат. Читать обратно руками.
- Смысл: не пересчитывать эмбеддинги при каждом запуске.
- Для MVP можно пропустить — но это 20–30 строк и оно сильно «думает» как прод-сторона.

## 10. Порядок коммитов (не перепрыгивай)

1. **A**: токенизатор + словарь + BoW-вектор. Прогнать на чанках, топ-1 логичен.
2. **B**: добавить IDF и нормализацию (TF-IDF). Сравнить топы A vs B.
3. **C** (опция): фильтр редких/стоп-слов, ё->е, мин-длина токена.
4. **D** (опция, прод): SVD снижение размерности.
5. **E** (опция): персистентность словаря+idf+индекса.
6. **F**: связать с VectorStorage через `Embedder`, затем заменить на `LlamaCppEmbedder`
   (llama.cpp embedding-режим, dim=384) — поменяется только реализация, не интерфейс.

## 11. Самопроверки «понял физику»

- [ ] Чанки про «кухню» дают друг другу косинус выше, чем «кухня» vs «окна».
- [ ] Удаление стоп-слова почти не меняет топы (в TF-IDF он и так маловесен).
- [ ] Редкий термин из запроса (например, «противопожарный») на Б поднимает нужный чанк выше, чем на А (BoW).
- [ ] После «заморозки» словаря векторы запроса и чанков всегда одной длины.
- [ ] Запрос, состоящий только из OOV-слов, не роняет программу (возвращает нулевой вектор).

## 12. Подводные камни (сюда смотреть, чтобы не переизобретать)

- Не добавляй токены в словарь после фита (размраживание = поломка размерностей).
- Порядок id — по первому вхождению, иначе непредсказуемые векторы/дампы.
- Целочисленное деление в tf/idf — кастай в float (см. шпаргалку про литералы: `static_cast<float>`).
- Сравнение `df` с нулём — формула со `+1` уже это страхует.
- Русский текст: приводи `ё`->`е`, не стрипай регистр криво (используй `std::towlower` под locale, либо простой ASCII-фильтр для MVP).
- Размерность: спарс-построение потом в плотный; не аллокать `vector<float>` V на каждый токен.
- Логируй `vocab_size()` + контролируй `storage.dim` = тот же размер.
