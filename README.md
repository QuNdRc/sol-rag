# solrag — retrieval-augmented generation по строительным нормам (C++20, Data-Oriented Design)

Локальный RAG-движок, написанный с нуля. Берёт запрос на русском языке, ищет
релевантные чанки в строительных сводах правил (СП/СНиП/ГОСТ) и генерирует ответ
с опорой на найденные нормы — всё на вашем компьютере, без облаков и API-ключей.

Построен без готовых векторных БД: плоское SoA-хранилище, семантический эмбеддер
(BGE-M3 через llama.cpp), инвертированный индекс BM25, гибридный поиск
(dense + sparse через Reciprocal Rank Fusion), генеративная LLM, LFU-выселение,
int8-квантизация и бинарная персистентность.

Зависимости: только llama.cpp (динамическая загрузка DLL через `GetProcAddress`,
без линковки) и стандартная библиотека C++20.

## Что внутри

| Компонент | Что делает |
|---|---|
| **Семантический поиск** | BGE-M3 (1024-мерные эмбеддинги, Q8_0), косинусное сходство, один линейный проход |
| **Лексический поиск** | Инвертированный индекс BM25 (k1=1.2, b=0.75), UTF-8 токенизация |
| **Гибридное слияние** | Reciprocal Rank Fusion (k=60) — dense + sparse в одном запросе |
| **Генеративная LLM** | Полный RAG-пайплайн: retrieved chunks → контекст → генерация ответа |
| **Чанкер с фильтром** | Разбивка по абзацам, отсев мусора: разделители, обрывки таблиц, штампы, преамбулы |
| **Параллельный поиск** | `std::jthread`, разделение диапазонов без гонок, куча на поток |
| **LFU-выселение** | Удаление чанков с минимальным счётчиком обращений (H2O-стиль) |
| **int8-квантизация** | Сжатие float32 → int8, ×4 экономия памяти, RMSE < 0.001 |

## Архитектура

```
 documents/*.txt
      |
      v
 Чанкер (абзацы, фильтр мусора)
      |
      v
 +---------------- HybridRag (фасад) ----------------+
 |                                                   |
 |  Embedder (BGE-M3)        Bm25Index               |
 |       |                       |                   |
 |       v                       v                   |
 |  RAG (dense, SoA)      инвертированный индекс     |
 |       |                       |                   |
 |       +----> rrf_merge <------+                   |
 |                (RRF, k=60)                        |
 +-----------------------|---------------------------+
                         v
                  Top-k чанков → LLM → ответ
```

### Ключевые решения

- **SoA (Structure of Arrays)**. Три независимых `std::vector`: координаты всех
  векторов одним монолитным массивом, тексты чанков параллельно индексам,
  счётчики доступа. Никакого массива структур — только линейные проходы,
  дружественные к кэшу процессора.

- **Абстрактный `Embedder`**. Ядро не знает, кто делает эмбеддинги.
  Интерфейс из одного метода `embed(text) → vector<float>`. Хоть BGE-M3,
  хоть TF-IDF, хоть самописный — подставляется без изменения поискового движка.

- **`HybridRag` — фасад, исключающий рассинхрон**. `add_chunk()` кладёт чанк
  сразу в dense- и sparse-индексы. Нельзя добавить в один и забыть про другой.
  `search()` ищет по обоим и сливает через RRF. Инвариант «id чанка в dense == id в BM25»
  гарантирован на уровне API, а не дисциплиной.

- **Динамическая загрузка llama.cpp**. `llama.dll`/`ggml.dll` загружаются
  через `LoadLibrary` + `GetProcAddress` — никакой линковки с llama.cpp,
  бинарник не зависит от версии lib. Модель — BGE-M3 567M Q8_0 (634 МБ).

- **Фильтр мусорных чанков**. Сырые тексты СП/ГОСТ содержат тонны метаданных:
  «УТВЕРЖДЕН приказом…», «Сведения о своде правил», преамбулы, обрывки таблиц,
  строки-разделители. Фильтр по доле букв, длине, чёрному списку фраз,
  детекту цифровых столбцов вырезает ~50% мусора: из 20 083 сырых чанков
  остаётся 10 067 осмысленных.

- **Русский стемминг и стоп-слова**. 10 суффиксов, нормализация ё→е,
  встроенный список стоп-слов — для TF-IDF эмбеддера и BM25.

##Запуск
Способ 1 (проще всего): двойной клик по run.bat.

Способ 2: Win+R → cmd → перетащить solrag.exe в окно консоли → Enter.

Способ 3: открыть консоль в папке с программой и набрать:

solrag.exe

Зависимости времени выполнения (рядом с `.exe`):

- `llama.dll`, `ggml.dll`, `ggml-base.dll`, `ggml-cpu-*.dll` — llama.cpp сборки b10063
- `libomp140.x86_64.dll` — OpenMP runtime

Интерактивная консоль:

```
[CONSOLE] Вводи запрос или команду: /stats, /bench N, /quit
```

| Ввод | Действие |
|---|---|
| Произвольный текст | Гибридный поиск (dense + BM25 + RRF) + генерация LLM |
| `/stats` | Число чанков и размерность |
| `/bench N` | Сравнение последовательного и параллельного поиска на N случайных векторах |
| `/quit` | Выход |

## Алгоритмы

| Алгоритм | Сложность | Примечания |
|---|---|---|
| Top-k min-heap | O(n log k) | Один проход, без полной сортировки O(n log n) |
| Параллельный поиск | O(n/P log k) | P = `hardware_concurrency()`, куча на поток, без гонок |
| LFU-выселение | O(n · dim) | Удаляется чанк с минимальным счётчиком доступа, стиль H2O |
| int8-квантизация | O(n · dim) | scale = range/254, zero = (min+max)/2, сжатие в 4 раза |
| BM25 | O(\|q\| · df) | k1=1.2, b=0.75, инвертированный индекс, UTF-8 |
| RRF-слияние | O(k₁ + k₂) | Reciprocal Rank Fusion, k=60 |
| Русский стемминг | O(\|t\| · \|suffixes\|) | 10 суффиксов, стоп-слова, нормализация ё→е |
| Бинарная персистентность | O(n · dim) | Строки с префиксом длины (UTF-8), плоский дамп float |

## Публичное API

Единственный публичный заголовочный файл — [`rag_core.h`](ConsoleApplication1/rag_core.h).
Он сам подтягивает модель данных и BM25; потребителю достаточно реализовать
`Embedder` (абстрактный класс с одним методом):

```cpp
#include "rag_core.h"

struct MyEmbedder : Embedder {
    std::vector<float> embed(std::string_view text) const override { /* ... */ }
};

MyEmbedder emb;
HybridRag rag(emb, 1024);
rag.load("rag_sem.bin");

auto hits = rag.search("запрос", 3);
for (auto& h : hits)
    std::cout << h.rrf << " " << rag.text(h.index) << "\n";
```

`HybridRag` — единый фасад над dense-индексом и BM25. `add_chunk()` кладёт
чанк в оба индекса, `search()` ищет по обоим и сливает через RRF.
Персистентность: dense-индекс сохраняется в бинарный файл, BM25 пересобирается
из текстов при `load()` (быстро, O(n)).
