# Sparse-RAG — векторная БД для RAG, написанная руками (C++20)

In-memory retrieval-движок для retrieval-augmented generation поверх
локальной LLM. Всё ядро написано с нуля: хранилище, **лексический** (TF-IDF) и
**семантический** (llama.cpp + MiniLM) эмбеддеры, поиск top-k, параллельность,
выселение, квантизация, персистентность — никаких готовых векторных БД.

Проект учебный/портфельный: цель — понимать, как векторная БД работает «под
капотом» (Data-Oriented Design, алгоритмы руками), а не просто обернуть ChromaDB.

## Что внутри

| Слой | Файл | Суть |
|---|---|---|
| Хранилище векторов (SoA) | `kakayatohuinya.h`, `ConsoleApplication1.cpp` | плоский `vector<float> all_dimensions`, чанк `i = i*dim`, поиск top-k |
| Поиск top-k | `ConsoleApplication1.cpp` | min-heap за O(n·log k) + параллельная версия на `std::jthread` |
| Эмбеддер (лексический) | `embedder.h`, `embedde.cpp` | BoW → TF-IDF + русские стоп-слова + стемминг |
| Эмбеддер (семантический) | `llama_embedder.h`, `llama_embedder.cpp` | llama.cpp b10063 → MiniLM (bert, dim=384), динамическая загрузка DLL |
| Границы интерфейса | `rag_core.h` | `Embedder` / `Chunker` / `RAG` — изолированная граница, ядро не зависит от эмбеддера |
| Демо / консоль | `main.cpp` | ингестия `documents/*.txt`, демо, бенчмарк, выселение, int8, интерактивный REPL |
| ТЗ проекта | `concept/concept.txt` | модель данных, thread-pool, выселение (стиль H2O) |

## Фичи (написаны руками)

- **TF-IDF** с русским стеммингом и стоп-словами. L2-нормализация на вставке → cosine = dot product.
- **Семантический эмбеддер**: llama.cpp `llama_encode` + `llama_get_embeddings_seq`,
  модель `paraphrase-multilingual-MiniLM-L12-118M-v2` (bert, dim=384, Q8_0).
  Мультиязычная (50+ языков, включая русский). Загружается динамически (GetProcAddress).
- **Top-k через min-heap**: O(n·log k), без полной сортировки массива.
- **Параллельный поиск**: N чанков делятся на `hardware_concurrency()` кусков,
  у каждого `std::jthread` своя min-куча, затем слияние. Гонок нет: каждый поток
  пишет только свой диапазон. Эквивалентность последовательному проверяется.
- **LFU-выселение** при лимите (по `access_counters`, в духе H2O из ТЗ).
- **int8-квантизация**: float→int8 (scale/zero), память x4 меньше, rmse ~1e-4.
- **Персистентность**: бинарные файлы — `rag_sem.bin` (векторы+тексты),
  строки length-prefixed UTF-8.
- **Интерактивная консоль** с русским вводом: программа сама ставит CP 65001,
  отдельный `chcp` не нужен.
- **CWD-независимость**: `documents/` и `models/` ищутся от CWD и от папки exe.

## Сборка (Windows, MSBuild)

```
MSBuild ConsoleApplication1.vcxproj /p:Configuration=Release /p:Platform=x64
```

Исполняемый файл: `ConsoleApplication1\x64\Release\ConsoleApplication1.exe`

**Зависимости времени выполнения** (должны лежать рядом с exe):
- `llama.dll`, `ggml.dll`, `ggml-base.dll`, `ggml-cpu-*.dll` — llama.cpp b10063
- `libomp140.x86_64.dll` — OpenMP runtime
- `models/paraphrase-multilingual-MiniLM-L12-118M-v2-Q8_0.gguf` — модель (119 MiB)

## Запуск

Запусти exe: двойной клик в Explorer, из `cmd` или из вкладки **Terminal** в IDE.

- первый запуск: загружает модель MiniLM, читает `documents/*.txt`, строит
  семантический индекс и сохраняет в `documents/rag_sem.bin`;
- повторные: загружает готовый индекс (`[SYSTEM] Семантический индекс загружен: N чанков`).

Дальше открывается интерактивный REPL:

```
[CONSOLE] Вводи запрос или команду: /stats, /bench N, /quit
```

| Ввод | Что делает |
|---|---|
| любой текст | top-3 чанка по базе знаний |
| `/stats` | число чанков и размерность |
| `/bench N` | бенчмарк последовательного против параллельного поиска на N чанках |
| `/quit` | выход |

> Если запускать из панели **Run** IDE (не Terminal) — stdin закрыт сразу и
> вводить клавиатурой нельзя; программа честно напишет об этом. Используй
> Terminal / Explorer / cmd.

## Куда развиваться

- **Генеративный LLM**: подключить генеративную модель (например, Gemma) через
  llama.cpp к тому же `llama_embedder.cpp` — получится полноценный RAG-пайплайн
  (эмбеддинг + генерация в одном процессе).
- **Гибридный поиск**: лексический (TF-IDF) + семантический (MiniLM) с
  переранжированием.
- **Данные**: файлы `documents/*.txt`. Чтобы перестроить индекс — удали
  `documents/rag_sem.bin`.
