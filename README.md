# SparseRAG — векторная база данных для RAG, написанная с нуля (C++20, Data-Oriented Design)

In-memory retrieval-движок для retrieval-augmented generation. Построен без готовых
векторных БД: плоское SoA-хранилище, лексический (TF-IDF) и семантический (BGE-M3)
эмбеддеры, min-heap top-k поиск, параллельное выполнение, гибридный поиск
(dense + BM25 через RRF), LFU-выселение, int8-квантизация, бинарная персистентность.

Зависимости: только стандартная библиотека C++20 и llama.cpp (динамическая загрузка
через `GetProcAddress`, без линковки).

## Архитектура

```
 documents/*.txt
      |
      v
 Чанкер (абзацы, фильтр мусора)
      |
      v
 +---------------- HybridRag (фасад) ----------------+
 |                                                   |
 |  Embedder (BGE-M3)        Bm25Index               |
 |       |                       |                   |
 |       v                       v                   |
 |  RAG (dense, SoA)      инвертированный индекс     |
 |       |                       |                   |
 |       +----> rrf_merge <------+                   |
 |                (RRF, k=60)                        |
 +-----------------------|---------------------------+
                         v
                  Top-k чанков + REPL
```

- **SoA (Structure of Arrays)**: три независимых `std::vector` — размерности, тексты,
  счётчики доступа. Без массива структур. Линейные проходы, дружественные к кэшу.
- **Интерфейс `Embedder`**: абстрактный класс. `TfIdfEmbedder` и `LlamaCppEmbedder`
  реализуют его и взаимозаменяемы — ядро не знает, кто внутри.
- **`HybridRag`**: фасад, который держит dense- и sparse-индексы в синхроне.
  `add_chunk()` кладёт чанк в оба индекса, `search()` ищет по обоим и сливает
  результаты через RRF. Рассинхронизация индексов (источник трудноуловимых багов)
  исключена на уровне API.
- **Чанкер**: разбивает по `\n\n`, отсеивает мусор: строки-разделители, обрывки
  таблиц, числовые столбцы, штампы метаданных («УТВЕРЖДЕН приказом...»),
  преамбулы документов («1.1 Настоящий свод правил...»).

## Алгоритмы

| Алгоритм | Сложность | Расположение | Примечания |
|---|---|---|---|
| Top-k min-heap | O(n log k) | `ConsoleApplication1.cpp` | Один проход, без полной сортировки O(n log n) |
| Параллельный поиск | O(n/P log k) | `ConsoleApplication1.cpp` | P = `hardware_concurrency()`, куча на поток, без гонок за счёт разделения диапазонов |
| LFU-выселение | O(n * dim) | `ConsoleApplication1.cpp` | Удаляется чанк с минимальным счётчиком доступа, стиль H2O |
| int8-квантизация | O(n * dim) | `ConsoleApplication1.cpp` | `scale = range/254`, `zero = (min+max)/2`, сжатие в 4 раза |
| BM25 | O(&#124;q&#124; * df) | `bm25_index.h` | k1=1.2, b=0.75, инвертированный индекс, UTF-8 токенизация |
| RRF-слияние | O(k1 + k2) | `rag_core.h` | Reciprocal Rank Fusion, k=60; результат = 1/(60+ранг) по каждому списку |
| Русский стемминг | O(&#124;t&#124; * &#124;suffixes&#124;) | `embedde.cpp` | 10 суффиксов, стоп-слова, нормализация ё→е |
| Бинарная персистентность | O(n * dim) | `ConsoleApplication1.cpp` | Строки с префиксом длины (UTF-8), плоский дамп float; BM25 пересобирается из текстов при загрузке |

## Подключение к другому проекту

Ядро — 4 файла (`glav.h`, `ConsoleApplication1.cpp`, `rag_core.h`, `bm25_index.h`)
плюс нужный эмбеддер. Минимальный сценарий:

```cpp
#include "rag_core.h"
#include "llama_embedder.h"

LlamaCppEmbedder emb;
emb.init("папка/с/dll", "models/Bge-M3-567M-Q8_0.gguf");

HybridRag rag(emb, emb.dim());
rag.load("rag_sem.bin");              // готовый индекс
// или rag.add_chunk(text);           // индексация с нуля

auto hits = rag.search("запрос", 3);  // гибрид: dense + BM25 + RRF
for (auto& h : hits)
    std::cout << h.rrf << " " << rag.text(h.index) << "\n";
```

Персистентность: сохраняется только dense-индекс (векторы + тексты),
BM25 пересобирается из текстов при `load()` — формат бинарника от этого не зависит.

## Сборка и запуск

```
MSBuild ConsoleApplication1.vcxproj /p:Configuration=Release /p:Platform=x64
```

Зависимости времени выполнения (рядом с исполняемым файлом):

- `llama.dll`, `ggml.dll`, `ggml-base.dll`, `ggml-cpu-*.dll` — llama.cpp b10063
- `libomp140.x86_64.dll` — OpenMP runtime
- `models/Bge-M3-567M-Q8_0.gguf` — эмбеддинг-модель (634 МБ)

Первый запуск строит индекс (~10 минут для 10 000 чанков). Последующие загружают
`documents/rag_sem.bin` за секунды.

Интерактивный режим:

```
[CONSOLE] Вводи запрос или команду: /stats, /bench N, /quit
```

| Ввод | Действие |
|---|---|
| Произвольный текст | Гибридный top-3 (dense + BM25, слияние RRF) |
| `/stats` | Число чанков и размерность |
| `/bench N` | Сравнение последовательного и параллельного поиска на N случайных векторах |
| `/quit` | Выход |
